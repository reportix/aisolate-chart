# Contributing

## Before you start

Read `README.md` and the hand-written part of `chart/README.md`. What the chart installs and what the cluster must
provide is AIsolate's documentation
([concepts](https://github.com/reportix/aisolate/blob/main/docs/concepts.md),
[install](https://github.com/reportix/aisolate/blob/main/docs/install.md),
[release](https://github.com/reportix/aisolate/blob/main/docs/release.md)). A change to the
chart's behaviour updates `chart/README.md` in the same merge request.

## Checks

```bash
README_GENERATOR_BIN=/opt/homebrew/bin/readme-generator-for-helm tests/chart/test.sh
```

You need `helm` and `yq`. `README_GENERATOR_BIN` names your build of readme-generator-for-helm (with the strict
schema and the `noReadme` modifier); without it the docs check is skipped, as in CI. `test.sh` checks that every
parameter a template reads is documented and every documented one read, that the parameter table and
`chart/values.schema.json` are generated from `chart/values.yaml` as they stand, that the renders match
`tests/chart/expected-results/`, and the render invariants. After an intended change,
`tests/chart/regenerate.sh` rewrites the table, the schema and the goldens; read the diff of the goldens, it is
the review of the render. A new behaviour gets an invariant in `tests/chart/verify-render-invariants.sh` that
fails when it breaks; a fix without one is not finished. CI (`.gitlab-ci.yml`) runs `test.sh` on every push and,
on a tag `<version>` that names `Chart.yaml`'s version, publishes the chart to the public Helm repository. Every
merge request bumps `version` in `chart/Chart.yaml`: CI's `verify-version` job fails a branch that does not.

## Repository layout

| Path | What |
|---|---|
| `chart/` | The chart: `Chart.yaml`, `values.yaml` with a `## @param` line per value, the generated `README.md` table and `values.schema.json`, the templates. |
| `chart/templates/platform/` | One folder per AIsolate component, its NetworkPolicy included. |
| `chart/templates/persistence/` | The backend's PostgreSQL. |
| `chart/crds/` | The custom resource definitions, generated by AIsolate's controller and copied here from the release's tag by `scripts/pin-release.sh`; never edited by hand. |
| `chart/examples/` | A production values file and an example Grafana dashboard. |
| `tests/chart/` | The checks, the values they render and the goldens. |
| `scripts/` | `pin-release.sh`, which pins the chart to an AIsolate release (README.md, Releasing). |
| `docs/assets/` | The logo. |

## Conventions

- `headless` decides only whether the AIsolate UI is installed. It gates templates and never names a folder.
- One folder per component, its NetworkPolicy included; values mirror the folders (`platform.backend` is
  `templates/platform/backend/`).
- Every value a template reads has a `## @param` line, and every `@param` is read.
- Images use the common image block; without `allowTags` a tag-only image fails the render.
- Object names, labels and selectors are API: the controller's peers and settings depend on them. The settings
  and the proxy's `envoy.yaml` live in pod templates, never in a ConfigMap.
- The chart holds no credentials, names no demo and installs no stand-in: the identity provider, the
  databases and the client applications are the organisation's.
- Comments say why, not what. Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `ci:`),
  one concern each. A merge request names the guarantee it touches.
