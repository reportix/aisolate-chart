# Contributing

## Checks

```bash
README_GENERATOR_BIN=/opt/homebrew/bin/readme-generator-for-helm tests/chart/test.sh
```

You need `helm`, `yq` and `jq`. `README_GENERATOR_BIN` names your build of readme-generator-for-helm (one that writes the strict
schema, `--strict`); without it the docs check is skipped, as in CI. `test.sh` checks that every parameter a template reads is
documented and every documented one read, that the parameter table and `chart/values.schema.json` are generated from
`chart/values.yaml` as they stand, that the renders of `tests/chart/values/*.yaml` (the default install, and everything on) match
`tests/chart/expected-results/`, and the render invariants. After an intended change `tests/chart/regenerate.sh` rewrites the
table, the schema and the goldens: read the diff of the goldens, it is the review of the render. A new behaviour gets an
invariant in `tests/chart/verify-render-invariants.sh` that fails when it breaks, whatever the goldens say; a fix without one is
not finished. A change to the chart's behaviour updates `chart/README.md` (or the README) in the same merge request.

CI (`.gitlab-ci.yml`) runs `test.sh` on every push, publishes every commit on the default branch to the internal Helm repository
as `<version>-<sha10>` and, on a tag `<version>` that names `Chart.yaml`'s version, the chart to the public one. Every merge
request bumps `version` in `chart/Chart.yaml`: CI's `verify-version` job fails a branch that does not.

## Conventions

- `headless` decides whether the AIsolate UI is installed; `platform.chat.enabled`, `platform.keycloak.enabled` and
  `platform.egress.proxy.domains` gate their component. A gate never names a folder: a gated template starts with its
  `{{- if … }}` and keeps its comments inside it.
- One folder per component, grouped by what it is (`platform/` for AIsolate's services, `persistence/` for databases). A
  component's folder holds all of it, its NetworkPolicy included, and values mirror the folders (`platform.backend` is
  `templates/platform/backend/`).
- Every value a template reads has a `## @param` line, and every `@param` is read. No `.Values.` in template comments.
- Images use the common image block (`registry`, `repository`, `tag`, `digest`, `pullPolicy`). An empty tag means the chart's
  `appVersion`. Without `allowTags`, a tag-only image fails the render. The AIsolate images but the UI's and the chat's default to
  `docker-public.sonatype.reportix.com`, their digests written by `scripts/pin-release.sh` (the UI's and the chat's registry and
  digest are the installer's until they are published); the third-party images (Keycloak, postgres, envoy, curl) carry the
  chart's own digest pin.
- `chart/crds/` is generated by AIsolate's controller and copied here from the release's tag by `scripts/pin-release.sh`; it is
  never edited by hand.
- Object names, labels and selectors are API: the controller's peers and settings depend on them. The controller parses its
  settings from the pod-template annotation `aisolate.dev/settings`, mounted as `/etc/aisolate/settings.yaml`. The settings and the
  proxy's `envoy.yaml` live in pod templates, never in a ConfigMap, so nobody who may write ConfigMaps rewrites them. Label keys
  and the `egress.hosts` hosts render as `"[key]"`, since the map binding keeps a key's dots only in brackets.
- The admin keeps egress: `platform.egress.hosts` maps the hosts of every LLM and data source defined for all of AIsolate or by a
  space or an airlock to their NetworkPolicy peers.
- The chart generates its own secrets (the Secrets `db`, `audit-ingest` and `credentials-key`, kept on upgrades) and holds none
  of the organisation's: no credentials, no space defaults. The identity provider, the databases and the client applications are
  the organisation's; the optional Keycloak, its demo users and the sample chat are off by default, for evaluation installs.
- Comments say why, not what. Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `ci:`), one concern each.
  A merge request names the guarantee it touches.
