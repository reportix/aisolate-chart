# AIsolate Helm Chart

AIsolate serves governed model endpoints over the organisation's own databases. This chart installs the custom resource
definitions (`Space` and `Airlock` of `aisolate.dev/v1`), the controller that turns them into airlock pods and tool server pods,
and the namespace's policies. How to install it and which values to set: the
[repository README](https://github.com/reportix/aisolate-chart#readme).

- `headless=true`, the default: no UI.
- `headless=false`: the AIsolate UI as well: its frontend, its backend (the UI's API and the CLI's endpoint) and the backend's
  PostgreSQL.
- `platform.chat.enabled`: the AIsolate chat, the sample client, on `platform.chat.host`, with or without the UI. Its image
  carries the release's URL from its build (`NEXT_PUBLIC_AISOLATE_URL`, a build arg of its Dockerfile), so build it for
  `platform.ingress.publicUrl`; add the chat's origin to `platform.airlock.corsAllowedOrigins`, since the browser calls the
  airlocks from it.
- `platform.keycloak.enabled`: a Keycloak of the chart's own on `platform.keycloak.host`, a demo and trial identity provider for
  evaluation installs, with the two realms AIsolate needs: `platform.keycloak.realms.operators` (default `aisolate`: the AIsolate
  UI and the CLI sign in there; realm roles `aisolate-admin` and `aisolate-auditor`) and `platform.keycloak.realms.users`
  (default `acme`: the chat signs its users in there; the roles the rules name are its realm roles). `platform.identity` and
  `platform.identity.operators` then default to those realms, and a value you set wins. The admin's password and, with
  `platform.keycloak.demoUsers`, each demo user's come from `platform.keycloak.existingSecret` or are generated into the Secret
  `keycloak`. Its data is on the PersistentVolumeClaim `keycloak`; the realms, and the login theme per realm
  (`platform.keycloak.realms.<realm>.loginTheme`, one the image carries), are imported into an empty one only: delete the claim
  to import them again. A production install points `platform.identity` and `platform.identity.operators` at the organisation's
  own provider.

## Keys, backups and the audit trail

With the UI, the backend's PostgreSQL keeps the spaces, the airlocks, the audit trail and the sealed credentials on the
PersistentVolumeClaim `db` (the cluster's default StorageClass unless `persistence.postgres.storage` names one). `helm uninstall`
deletes it: back it up, the audit trail is only as durable as that database.

The chart generates three Secrets on the first install and keeps them on upgrades: `db`, the database's password (the backend
and the database read it); `audit-ingest`, the ingest key (the controller derives each airlock's tokens from it and the backend
checks them: only those two read it); and `credentials-key`, the key the backend seals every typed model API key and data source
login with, AES-256-GCM (only the backend reads it). Losing that key loses every stored credential: back it up with the database.
The Secrets the pods already hold keep working, and re-entering a credential in the UI makes it revealable again. Where the chart
is rendered without cluster access (Argo CD, `helm template`) it cannot keep a generated key: set the matching `existingSecret`;
rolling the pods after a rotation is then yours.

Each airlock pod hands its audit lines to the backend's ingest port 8085 (`POST /v1/audit/events`), and each airlock and tool
server pod fetches its code from it at start (`GET /v1/code/<space>/<airlock>/<digest>`), each with a token the controller
renders for that airlock alone. Only those pods reach the port and no Ingress routes to it. The backend keeps the lines
append-only and hash-chained per airlock. A headless install has no backend: the pods print the lines to stdout alone, nothing
fails closed, and an airlock runs without code only. The API host's Ingress takes a body of any size, so
`platform.backend.maxArtifactSize` (for example `500MB`) is the limit. What a line holds and how the chain is checked: AIsolate's
[audit documentation](https://github.com/reportix/aisolate/blob/main/docs/audit.md).

## Observability

AIsolate plugs into the monitoring the cluster already runs; the chart installs none of it. It speaks OTLP for traces and the
Prometheus text format for metrics, so any backend that reads them works (all Apache-2.0: the OpenTelemetry Collector in front of
Jaeger, and Prometheus).

- **Traces:** set `platform.observability.otlpEndpoint` to your collector's OTLP/HTTP base URL, for example
  `http://otel-collector.monitoring.svc:4318` (the pods append `/v1/traces`), and map its host in `platform.egress.hosts`: an
  endpoint whose host is neither mapped nor proxied makes every space `Invalid`. Empty, the default, sends nothing.
- **Metrics:** the controller, the backend, and every airlock and tool server pod serve `/actuator/prometheus` without a token on
  the management port 9464 (container port `management`), which no Service and no Ingress exposes. Their NetworkPolicies admit a
  pod labelled `aisolate.dev/scraper: "true"` from any namespace on 9464 alone: label your Prometheus or agent pods with it and
  scrape the `management` port. `examples/grafana-dashboard.json` is a Grafana 11 dashboard over these series (import it and pick
  your Prometheus); the series name no space, so copy the pod label `aisolate.dev/space` onto a `space` label when you scrape
  (`target_label: space` from `__meta_kubernetes_pod_label_aisolate_dev_space`).
- **Monitoring in the UI (`headless=false`):** `platform.tracing.queryUrl` (Jaeger's query API, or any store that answers
  `GET /api/traces/{id}` alike) adds Monitoring > Tracing, and `platform.metrics.queryUrl` (Prometheus's HTTP API) adds its
  Metrics tab, from fixed queries each caller's spaces alone; each needs its `egress` peer, and the metrics the `space` label
  above. The backend reads the stores, the browser never calls them. Empty, the default, hides them.

What the spans and the series hold, and never hold: AIsolate's
[observability documentation](https://github.com/reportix/aisolate/blob/main/docs/observability.md).

## Uninstallation

`helm uninstall aisolate --namespace aisolate` keeps the CRDs, and with them every `Space` and `Airlock`; `kubectl delete -f
chart/crds` removes those as well.
