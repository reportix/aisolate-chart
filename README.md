# AIsolate Helm chart

[![License: AGPL-3.0-only](https://img.shields.io/badge/license-AGPL--3.0--only-blue.svg)](LICENSE)

The Helm chart that installs [AIsolate](https://gitlab.reportix.com/aisolate/control-plane) on Kubernetes:
governed model endpoints over the organisation's own databases. The chart is `chart/`, its tests are
`tests/chart/`.

## What the chart installs

Everything goes into one namespace. Always: the custom resource definitions (`Space` and `Airlock` of
`aisolate.dev/v1`), the controller that turns them into airlock pods and tool server pods (the Java and the
Python images, `platform.airlock`, `platform.toolServer`, `platform.airlockPython` and
`platform.toolServerPython`), the namespace's default-deny NetworkPolicy and one policy per component, the
`aisolate` Service and Ingress for discovery and `/.well-known/`, and, when `platform.egress.proxy.domains` is
set, the CONNECT-only egress proxy. `headless=false` adds the AIsolate UI: its frontend, its backend and the
backend's PostgreSQL, a database on a PersistentVolumeClaim that only the backend reaches.
`platform.chat.enabled` adds the AIsolate chat, the sample client, on its own host.
`platform.keycloak.enabled` adds a Keycloak of the chart's own, with a realm for the operators and one for the
application users, so that a cluster without an identity provider is complete.

What the controller renders per airlock, how the two kinds of install differ and what the cluster, the identity
provider, the databases and the model server must provide is the control plane's documentation:
[install](https://gitlab.reportix.com/aisolate/control-plane/-/blob/main/docs/install.md),
[release](https://gitlab.reportix.com/aisolate/control-plane/-/blob/main/docs/release.md) and
[concepts](https://gitlab.reportix.com/aisolate/control-plane/-/blob/main/docs/concepts.md).

## Install

Create the namespace and label it for the restricted Pod Security Standard first: Helm does not manage the
release namespace.

```bash
kubectl create namespace aisolate
kubectl label namespace aisolate pod-security.kubernetes.io/enforce=restricted
```

Every tag `v<version>` publishes the packaged chart with a GitLab release of this project:

```bash
helm install aisolate \
  'https://gitlab.reportix.com/aisolate/charts/-/jobs/artifacts/v0.1.0/raw/aisolate-0.1.0.tgz?job=chart-publish' -n aisolate --create-namespace -f values.yaml
```

From a checkout, `helm install aisolate chart -n aisolate -f values.yaml`. The values file carries every
AIsolate image by digest (without `allowTags` a tag-only image fails the render), the identity provider under
`platform.identity` and the peers under `platform.egress`: the cluster's DNS, ingress and API server, and in
`hosts` the hosts of every LLM and data source defined for all of AIsolate or by a space or an airlock.
[chart/README.md](chart/README.md) walks through the install and lists every parameter.

`chart/crds` is generated by the control plane's controller and copied here; apply it with
`kubectl apply --server-side -f chart/crds` before `helm upgrade`, since Helm installs CRDs on the first install
only. Once a `Space` exists, `helm test` checks from a pod that the release answers through the ingress controller
and that its discovery pods are unreachable, and after a deploy that the tool server Services in
`test.toolServers` are too; before that, it reports those probes as skipped.

## Tests

`tests/chart/test.sh` checks that every parameter a template reads is documented and every documented one read,
that `chart/README.md`'s parameter table and `chart/values.schema.json` are current, that the renders of
`tests/chart/values/*.yaml` and of `chart/examples/` match `tests/chart/expected-results/`, and the render
invariants (`verify-render-invariants.sh`): one namespace, every pod restricted on a read-only root and its
image by digest; the network opened to each component's peers alone; the generated Secrets and the settings in
no ConfigMap; the Roles bounded to what each component does. After an intended change, `regenerate.sh` rewrites
what they compare against. You need `helm` and `yq`; `README_GENERATOR_BIN` names the readme generator (a build
of readme-generator-for-helm with the strict schema and the `noReadme` modifier), without which the docs check
is skipped. CI runs the same script on a public image with checksum-verified `helm` and `yq`, and packages the
chart as a release on a tag `v<version>`.

## Conventions

- `headless` decides only whether the AIsolate UI is installed. It is the chart's only switch; it gates
  templates and never names a folder.
- One folder per component, grouped by what it is (`platform/` for AIsolate's services, `persistence/`
  for databases). A component's folder holds all of it, its NetworkPolicy included, and values mirror the
  folders (`platform.backend` ↔ `templates/platform/backend/`).
- Every value a template reads has a `## @param` line, and every `@param` is read. No `.Values.` in
  template comments.
- Images use the common image block (`registry`, `repository`, `tag`, `digest`, `pullPolicy`,
  `pullSecrets`). An empty tag means the chart's `appVersion`. Without `allowTags`, a tag-only image fails
  the render; the third-party images (postgres, envoy, curl) carry the chart's own digest pin.
- Object names, labels and selectors are API: the controller's peers and settings depend on them. The
  controller parses its settings from the pod-template annotation `aisolate.dev/settings`, mounted as
  `/etc/aisolate/settings.yaml`. The settings and the proxy's `envoy.yaml` live in pod templates, never in a
  ConfigMap, so nobody who may write ConfigMaps rewrites them. Label keys and the `egress.hosts` hosts render as
  `"[key]"`, since the map binding keeps a key's dots only in brackets.
- The admin keeps egress: `platform.egress.hosts` maps the hosts of every LLM and data source defined for
  all of AIsolate or by a space or an airlock to their NetworkPolicy peers. The chart holds no credentials and no space
  defaults; it generates the backend database's password into the Secret `db` at install and keeps it on
  upgrades.
- A gated template starts with its `{{- if … }}` and keeps its comments inside the gate.
- The chart names no demo and installs no stand-in: the identity provider, the databases and the client
  applications are the organisation's.
